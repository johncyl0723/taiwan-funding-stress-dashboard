# 台灣資金緊俏每日儀表板

公開市場研究用途的台灣短期資金監測工具。線上：<https://johncyl0723.github.io/taiwan-funding-stress-dashboard/>

版面分三部分：

1. **今天資金緊不緊** —— TSS 綜合指數、燈號、規則式摘要、AI 短評、走勢圖、相關新聞
2. **TSS 怎麼組成的** —— 依知識圖譜由上而下展開（外生驅動 → 央行政策 → 銀行間價格 → 票券與企業融資 → 合成與判讀），
   每個指標左圖右文，右欄固定分成「這個指標在量什麼」與「現在的數字說什麼」；月頻與週頻背景另置一帶
3. **台幣 vs 美元** —— 外幣通道，結構同第二部分

## 兩種文字，來源不同

畫面上的文字有兩個來源，分開標示，不可混淆：

| 區塊 | 來源 | 失效時 |
| --- | --- | --- |
| **規則式摘要**、各指標的「現在的數字說什麼」 | `scripts/lib/insight.ts` 依當日數據套用預寫規則產生，不經 AI | 永遠存在 |
| **AI 短評／新聞摘要** | GitHub Action 內呼叫一次 LLM，把生成結果存進 `dashboard.json`，頁面本身仍是純靜態 | 未設任何憑證或呼叫失敗時整段留空，其餘照常發布 |

AI 文字的 prompt 只餵入當日數據、被排除的子指標與新聞標題（或新聞稿全文），並要求「不得引入未提供的數字」
「不得提供投資建議」；新聞摘要另外要求把新聞內容當「資料」而非指令。輸出未經人工審閱，畫面上明確標示
模型名稱、生成時間與免責聲明。

### 兩種後端，優先用訂閱

`scripts/lib/commentary.ts` 依序嘗試：

1. **Claude Code 訂閱**（`CLAUDE_CODE_OAUTH_TOKEN` 有設定就用這個）—— 不計量計費，吃訂閱額度
2. **OpenAI API**（`OPENAI_API_KEY`）—— 計量計費
3. 兩者都沒有 → 整段跳過，規則式文字不受影響

兩者都設定時只用 Claude Code，失敗不會偷偷改打 OpenAI（避免「明明只設了訂閱，帳單卻跑去別的服務」）。

**用 Claude Code 訂閱（建議，個人使用免計量計費）**

這條路是官方支援的：`claude setup-token` 產生的 OAuth token 綁定 Pro/Max/Team/Enterprise 訂閱，
Anthropic 自己的 GitHub Actions 排程範例（Daily Report）就是同樣「非程式相關、定期產生摘要」的用法，
用訂閱額度執行而不計入 API 帳單。詳見 [code.claude.com/docs/en/authentication](https://code.claude.com/docs/en/authentication)
與 [code.claude.com/docs/en/github-actions](https://code.claude.com/docs/en/github-actions)。

1. 本機裝好 `claude` CLI 並登入你的 Pro/Max 帳號後，執行：
   ```bash
   claude setup-token
   ```
   瀏覽器授權完會印出一個一年期的 token。
2. 到 repo 的 **Settings → Secrets and variables → Actions** 新增 secret `CLAUDE_CODE_OAUTH_TOKEN`，貼上這個 token。
3. 選用：新增 repository variable `CLAUDE_CODE_MODEL`（預設 `haiku`，可設 `sonnet`／`opus`）。

Token 一年到期，屆時要重新跑一次 `claude setup-token` 換新的。這個 token「只能發模型請求」，
不能建立 Remote Control 連線或讀 claude.ai connectors，外流風險比一般帳密低，但仍要當機密保管
（跟 API key 同等對待，只放在 repo secret，不要出現在程式碼或 log 裡）。

**用 OpenAI API（備援／若不想用訂閱）**

到 repo 的 **Settings → Secrets and variables → Actions** 新增 secret `OPENAI_API_KEY`。
模型預設 `gpt-5-mini`，可用 repository variable `OPENAI_MODEL` 覆寫 —— 模型 ID 會隨時間汰換，
寫死會讓排程在某天突然失敗。以每日一次、輸入約 1,500 token 估算，月成本約數美分。

**其他實作細節**：跑 `claude` CLI 需要 Node.js 22+（workflow 已設定），且**刻意不加 `--bare`**——
官方文件明講 bare 模式不讀 `CLAUDE_CODE_OAUTH_TOKEN`（只認 API key），加了會驗證失敗。
新聞摘要在 Claude Code 這條路用 `--json-schema` 直接拿結構化的 `{official, media}`，
不必再用正規表示式拆「官方：／媒體：」兩行文字；OpenAI 沒有對應機制，仍用文字格式＋解析。

## 新聞與 AI 摘要

兩種來源可用的素材差很多，摘要方式因此不同 —— 這個不對稱在畫面上會明講：

| 來源 | 取得的內容 | 摘要依據 | 標示 |
| --- | --- | --- | --- |
| 央行新聞稿 RSS | 標題＋**完整新聞稿內文**（政府公開資訊） | 全文，可保留具體數字 | 「摘要依據新聞稿全文」 |
| Google News RSS | **只有標題** | 標題歸納出的主題 | 「摘要僅依據標題」（警示色） |

**媒體全文刻意不抓**：有版權與付費牆限制，而且外部網頁內容是提示詞注入的典型載體。
媒體標題與摘要都不參與任何指標計算，原始標題與連結一律保留在摺疊區供查閱。

摘要的 system prompt 明確要求把新聞內容當「資料」而非指令 —— 即使其中出現看似指示或
宣稱更高權限的文字，也只能當被引用的內容看待。摘要與資金行情短評是兩次獨立呼叫，
任一失敗都不影響另一個，也不影響資料更新。

## 燈號怎麼算

**綜合指標**＝五個日頻子指標各取 120 日 z-score 後等權平均，燈號以 5 日均值判定：

| 子指標 | 內容 | 材料性門檻（120 日標準差） |
| --- | --- | --- |
| TFSS | 90D TAIBIR 初級 − 3M TAIBOR | 0.25 bp |
| 初級－次級利差 | 90D TAIBIR 初級 − 次級 | 0.25 bp |
| TAIBOR 斜率 | 3M − 1W | 0.25 bp |
| O/N 走廊位置 | (隔拆 − 7 天期 NCD 利率) ÷ (重貼現率 − 7 天期 NCD 利率) | 0.01 |
| NCD 淨發行 | 近 5 個交易日合計 | 5,000 百萬元 |

門檻：5 日均 z ≥ 1.0 開始偏緊、≥ 1.5 明顯緊俏、≥ 2.0 異常壓力。

### 四個判讀修正器

1. **材料性檢定**：z-score 是尺度無關的，序列再平也算得出 2σ。實測 TAIBOR 斜率的 120 日標準差只有 0.08 bp、O/N 走廊位置只有 0.0026，若照樣等權納入，0.2 bp 的擺動就會主導頭條燈號。未達門檻的子指標會被排除，並在畫面與摘要中列出原因。
2. **絕對水準 guard**：純相對分位在升息週期會系統性誤報。TFSS 仍低於 30 bp 且 O/N 貼近走廊下限時，燈號最高只給「開始偏緊」。
3. **5 日均值**：燈號以 composite 的 5 日移動平均判定，當日值只顯示不判燈，避免單日雜訊。
4. **事件旗標**：稅期、除息旺季、季底年底、農曆年前、央行理監事會前後。旗標亮起時在摘要標註「屬季節性」，但**不**升級燈號。

### 兩種「沒有燈號」

- **待資料確認**：樣本不足 30 個交易日，或當日核心指標未同步定盤。
- **正常（市場無明顯波動）**：資料完整，但每個子指標的變異都低於材料性門檻。台灣短率由央行主導、極為黏著，長時間毫無變異是常態 —— 這種安靜必須與資料有問題分開，否則會把「市場很平靜」誤報成「工具壞了」。

## 已知限制

- **TFSS 不是純粹的資金鬆緊指標**。分子是票券初級市場（企業信用），減項是銀行間定盤利率，價差同時含信用溢酬與流動性溢酬，性質接近 TED spread。
- **政策升息不會、也不應該點亮燈號**。升息時 TFSS 兩隻腳同步上移，價差不變甚至收斂。回測已驗證 2022-03、2023-03、2024-03 三次升息皆未誤報。
- **門檻尚未經過真實壓力事件校準**。回測區間（2022 年起，受 TAIBOR 公告清單深度限制）不含任何真實資金壓力事件，分位數建議門檻只會把燈號固定點亮 20%／8%／2% 的時間，不是校準，因此維持常態近似初值。
- **外幣通道缺少換匯點**，只能給名目利差與匯率波動，算不出避險後的隱含台幣成本。臺灣銀行遠期牌告尚未接上。
- **公債附條件（RP）利率未接上**：櫃買中心拒絕自動抓取。
- **存放比未接上**：央行「重要金融指標」只提供 XLS／ODS／PDF，需要試算表解析器。

### 抓取實作重點

- **集保 TAIBIR**：官網只有「當日」頁面，改用歷史區間查詢（POST ＋ CSRF token ＋ session cookie）。`SYNCHRONIZER_TOKEN` 是一次性的，每個區段都必須重新 GET 表單頁；單次查詢上限約 170 天，長區間自動切段。
- **TAIBOR**：數字不在網頁文字中，而在公告附的 Big5 CSV。每日公告附近 40 天、月報附整月；公告清單以 `?page=N` 翻頁，日常更新只讀第 1 頁，回測依區間長度翻頁。
- **央行 NCD**：金額只在「公開市場操作資訊」公告，「存單申購發行資訊」沒有金額，需以標題過濾。解析範圍必須切到公告本文（`一、`～`檔案下載`）—— 央行每頁的左側選單都有「小規模附買回測試操作」，整頁比對會天天誤報附買回。
- **欄位一律依表頭文字定位**（`90`、`三個月`、`本期超額或不足`），官網改欄序時直接報錯，而非靜默取到錯誤天期。
- **編碼自動判斷**：銀行公會 CSV 是 Big5、央行 OpenData 是 UTF-8 BOM，以表頭關鍵字是否解碼成功決定。
- **日期一律台北時間**（UTC+8），避免 UTC 換日造成整批資料錯位一天。
- **降級策略**：TAIBIR 初級與 TAIBOR 為核心來源，缺任一則整批不發布；其餘缺漏只讓該欄位為空值，並在畫面標示讀取狀態。
- **歷史合併**：每次更新向官方要一整段區間（預設 200 天）而非單日，首次執行即可取得約 140 個交易日的統計基期。NCD 與外資只回補約 12 個交易日，合併時舊值不會被清空。

## 架構

純靜態網站，全部跑在 GitHub 上：

- **前端**：Vite + React，發布到 GitHub Pages
- **資料更新**：GitHub Actions 排程（UTC `0 4 * * 1-5`，即台灣時間週一至週五 12:00）跑測試後執行 `scripts/refresh.ts`，寫回 `public/data/` 並自動 commit
- **文字**：規則式模板（`scripts/lib/insight.ts`）＋ 選用的 OpenAI 短評（`scripts/lib/commentary.ts`），見上方「兩種文字」
- **手動更新**：到 repo 的 Actions 頁籤，選 `更新資料並部署` → `Run workflow`

沒有伺服器、沒有資料庫、沒有登入機制。唯一會產生費用的外部服務是選用的 OpenAI 短評（每日一次呼叫，未設金鑰即不啟用）。

## 本機啟動

```bash
npm install
npm run dev
```

```bash
npm run refresh
```

```bash
npm test
```

本機要試 AI 短評，在專案根目錄放一個 `.env`（已列入 `.gitignore`）或直接設環境變數：

```bash
# 用 Claude Code 訂閱（需先本機跑過 claude setup-token）
CLAUDE_CODE_OAUTH_TOKEN=... npm run refresh

# 或用 OpenAI
OPENAI_API_KEY=sk-... npm run refresh
```

回測與門檻檢查（一次性工具，不在每日排程內；TDCC 逐段查詢會花數分鐘）：

```bash
npm run backtest -- --from=2022-01-01
```

加 `--full` 會把逐日序列一併寫入輸出檔（數 MB，僅供本機檢視）。
